## 全局靶子

- **目标**：做出一个你自己天天会用的**单人版 todolist**，并且看懂它的每一层是怎么来的——你负责指挥 agent 与逐条核对，长出识别力。
- **预期结果**：浏览器里跑着一个可增删、可勾选完成的 todolist，界面即时跟随数据变化；同一份功能经历了五次重写（HTML → JS → CSS → React → React+TS+Tailwind），你能对照任意两个版本，指出「这一层替你做了什么」。持久化（刷新不丢）是后续后端章的靶子，本主线先不承诺。
- **积木清单**（从预期结果倒推，只列用到的）：HTML 骨架与标签、DOM 查询与操作、JS（变量/数组/事件）、CSS（内联样式/样式文件/选择器）、React 组件与 state、props、TypeScript 类型、TailwindCSS 工具类、Vite 开发服务器与构建产物。
- **贯穿线——全栈的核心是「数据控制」**：界面是数据的影子。谁拥有数据、数据怎么变、变化怎么走到界面上——3.2 里你用 JS **手动**控制，4.1 里 React **声明式**地替你控制，4.2 里 TS 给数据**定型**，后端章（待定）回答**数据住在哪里**。每一章都回扣这句话。
- **环境**：两条练习路线任选，第 2 章展开——① 线上 playground：本站自带，浏览器里跑真实工程（WebContainer）＋陪练 agent，填一个 API key 即用；② 本地：你自己的机器 + 你自己的 agent。
- **时间投入**（预估，实现时校准）：纯通读约 1–1.5 小时；边读边跟练约 4–6 小时，建议分 2–3 次；环境搭建一次性投入 30 分钟–1 小时。

## 2. 环境处理和搭建

- **靶子**：目标＝有一个你和你的 agent 能随时动手的工程环境。预期＝在环境里改一行代码，浏览器跟着变；agent 能替你执行命令、你能在真机上核对结果。积木＝Node/npm、Vite 开发服务器、WebContainer、agent 工具调用。
- **步骤**：
  1. **2.1 本地环境**【代理区 + 价值区】——脚手架交给本地 agent 搭（代理区）；**认知基础就地露出**：node / npm / 终端 / dev server 各是什么、为什么存在——平台替读者屏蔽这些，教程不能。**真机验收**：`node -v` 有版本、dev 服务器起来、改一行浏览器跟着变——跑必须真跑，agent 代装可以，代跑不行。
  2. **2.2 线上 playground**【价值区】——引导打开 `/practice.html`，陪练 agent 填 API key（仅存读者浏览器 localStorage），跑起模板工程。验收：在 playground 里完成与 2.1 相同的「改一行看变化」。
  3. **2.3 环境细节（工具书式）**——package.json / node_modules / dev 与 build / 端口与代理，按查阅组织，明确「不要求通读，卡住再查」。
- **指派学习**：npm 一族。位置＝包管理与工程脚本，旁边是 lockfile 与 registry。预期＝能对照 package.json 向 agent 讲清 devDependencies 与 scripts 各管什么。场景＝给工程加一个依赖并删掉它；改 dev 端口再改回来。
- **脱靶提醒**（备注在 2.1/2.2 后）：
  - 命令全成功但页面空白——缺「真机验收」这块：网页要从服务**跑起来**，不是文件双击。
  - playground 里 agent 不动——先看 key 与控制台报错；WebContainer 启动失败多半是网络到 StackBlitz 不通，页面有明确报错提示（见练习页错误态）。

## 3. 前端入门

- **靶子**：目标＝不借任何框架，徒手让浏览器听你的。预期＝纯 HTML/JS/CSS 的 todolist：增删待办、界面跟着数据变、有基本样式；代码里找不出任何「框架魔法」。积木＝HTML 标签、DOM、JS 变量/数组/事件、CSS 内联与样式文件。
- **步骤**：
  1. **3.1 Hello World**【价值区】——写第一个页面，HTML 三件套结构与常用标签就地露出（标题/段落/列表/按钮）。验收：浏览器渲染出你写的标题与一句话，且你能指出每个标签对应屏幕上的哪块。
  2. **3.2 数据驱动视图**【价值区】——一个数组渲染成列表；增删待办＝改数组＋重新渲染。积木三句话：DOM（浏览器给你的界面操作口）、事件（用户动作的入口）、数组（待办数据的家）。**回扣贯穿线**：这是数据控制最原始的形态——数据变了，你**亲手**把界面重画一遍。验收：增删待办界面即时变化；能指着代码说出「数据住在这个数组、重画走这个函数」。
  3. **3.3 给 todolist 穿衣服**【价值区】——同一批样式用**内联样式**与**CSS 文件**各做一遍，两种形式就地把工程区别讲清：内联＝快、局部、难复用；文件＝可维护、可复用、需要约定——这是工程上的分界，不是语法上的。验收：两种方式各实现同一效果，且能说出「什么场合用哪种」。
- **指派学习**：CSS 选择器一族。位置＝「样式如何命中元素」，旁边是优先级与继承。预期＝不看文档能写出交集、后代、伪类三种选择器并讲清各命中谁。场景＝只给「已完成」的待办加删除线；鼠标悬停时整行变色。
- **脱靶提醒**（备注在 3.2 后）：
  - 功能对但 DOM 越改越乱、出现「幽灵节点」——缺「数据是唯一事实源」这块：每次都从数组重画，不要零散补丁。
  - 刷新后待办全丢——这不是 bug：数据还只住在内存里，持久化是后端章的靶子，先记下这个痛。

## 4. 前端行业常用框架

- **靶子**：目标＝把同一支 todolist 迁到行业标配，理解每一层「为什么存在」。预期＝React + TS + Tailwind 的 todolist，功能与第 3 章完全一致；对照 3.x 的代码，能指出框架替你做了什么、你失去了什么自由。积木＝React 组件与 state、props、TypeScript 类型、TailwindCSS 工具类、Vite 构建。
- **步骤**：
  1. **4.1 React 改写**【价值区】——state 驱动替代 3.2 的手动重绘。积木三句话：组件（界面的零件）、state（组件的数据）、props（父到子的数据流）。**回扣贯穿线**：React 把「数据变了界面跟着变」从手工劳动变成一句声明。验收：增删待办的代码里不再出现手动 DOM 操作，界面照样更新。
  2. **4.2 React + TS**【价值区】——给待办数据定型（Todo 接口：id/text/done）。验收：故意把字段名拼错，编译期就报错——agent 给的代码里这类错误从此瞒不过你。
  3. **4.3 Tailwind 改写样式**【价值区】——3.3 的样式全部改写为工具类。验收：视觉与 3.3 一致，且你能说出工具类与样式文件各自的取舍（回到 3.3 的工程分界）。
  4. **4.4 游览产出物**【价值区】——把第 3 章纯静态、本章 dev 服务器、build 后的 dist 三种产物摆在一起看。**认知基础就地露出**：构建器在做什么、dev 与 prod 差在哪。验收：能指出 dist 里每个文件对应源码哪一层，并说清为什么 dist 能直接部署而 dev 不能。
- **指派学习**：状态提升一族。位置＝React 数据流——多个组件共享一份数据时数据该住谁家，旁边是 props 向下、事件向上。预期＝给 todolist 加一个「筛选条」（全部/未完成），能说清筛选状态为什么住在列表的父组件。场景＝筛选条与列表联动；计数徽标显示剩余数。
- **脱靶提醒**（备注在 4.1 后）：
  - 照抄能跑，但答不出「数据住谁家、谁负责重画」——缺 state 数据流这块，回 3.2 对照手动版本。
  - 改了数组界面不动——多半是直接改了原数组没换新引用：React 靠「引用变了」才知道要重画，这是它与 3.2 手动模式的本质差别。
